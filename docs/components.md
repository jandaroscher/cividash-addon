# Components

The add-on is deployment logic only. This list names everything a deployment
consists of and where its bill of materials comes from. Update it when the
chart, the tasks or the images change.

## Shipped in this repository

| Component | What it is | Licence |
| --- | --- | --- |
| Ansible tasks (`tasks.yml`, `tasks/`, `templates/`) | Platform hook that provisions the database, Keycloak clients and the APISIX route, then installs the chart | EUPL-1.2+ |
| Helm chart `chart/cividash` | Deployments, Jobs, Services, Ingress/HTTPRoute and Secrets for CiviDash; no subcharts | EUPL-1.2+ |

## Deployed images

| Image | Pinned in | SBOM |
| --- | --- | --- |
| `ghcr.io/jandaroscher/cividash-app` | `vars/software_references.yml` | `cividash-app-<cividash-version>.spdx.json`, where `<cividash-version>` is the pinned image tag; attached to every add-on release from 1.8.0 on, copied from the CiviDash release of that version |
| `ghcr.io/jandaroscher/cividash-web` | `vars/software_references.yml` | `cividash-web-<cividash-version>.spdx.json`, same |

The chart starts no other images. The SBOMs are SPDX JSON, generated by Syft in
the CiviDash release pipeline from the `linux/amd64` image variant (the
`linux/arm64` variant differs only in its Alpine binaries); the `Release SBOM`
workflow copies them to the add-on release. They describe the default images
pinned in `vars/software_references.yml` only; a deployment that sets
`inv_addons.cividash.images.{app,web}.*` runs other images, which these SBOMs do
not cover.

## Provided by CIVITAS/CORE

The add-on brings none of these; the CORE platform or its operator provides them:

- Ansible collections `ansible.builtin` and `kubernetes.core` (`k8s`, `k8s_info`), and the CORE Helm task wrapper that installs the chart
- Keycloak (realm, shared `api-access` client, tenant groups)
- APISIX (route to `cividash-web`) and the ingress controller (Traefik by default) or Gateway API
- PostgreSQL operator with `central-db`, when `db.central: true`
- S3-compatible object storage for media (bucket and credentials from the operator)
