# Components

The add-on is deployment configuration only. This list names everything a
deployment consists of and where its bill of materials comes from. Update it
when the component files, the chart or the images change.

## Shipped in this repository

| Component | What it is | Licence |
| --- | --- | --- |
| CIVITAS/CORE 2 component files (`civitas-component.yaml`, `charts.yaml`, `images.yaml`, `default-environment.yaml.gotmpl`, `helmfile.yaml.gotmpl`, `values/`, `keycloak-clients.yaml`, `databases.yaml`, `secrets.yaml`, `networkpolicies*.yaml`, `policy-exceptions.yaml`) | Declare what CORE creates for CiviDash and how it installs the chart | EUPL-1.2+ |
| Helm chart `charts/cividash` | Deployments, Jobs, Services, Ingress (optional HTTPRoute), hook Secrets, PodDisruptionBudgets, Linkerd `Server` and the optional media volume; no subcharts | EUPL-1.2+ |

## Deployed images

| Image | Pinned in | SBOM |
| --- | --- | --- |
| `ghcr.io/jandaroscher/cividash-app` | [`images.yaml`](../images.yaml) | `cividash-app-<cividash-version>.spdx.json`, where `<cividash-version>` is the pinned image tag; attached to every add-on release, copied from the CiviDash release of that version |
| `ghcr.io/jandaroscher/cividash-web` | [`images.yaml`](../images.yaml) | `cividash-web-<cividash-version>.spdx.json`, same |

The chart starts no other images. The SBOMs are SPDX JSON, generated by Syft
in the CiviDash release pipeline from the `linux/amd64` image variant (the
`linux/arm64` variant differs only in its Alpine binaries); the
`Release SBOM` workflow copies them to the add-on release. They describe the
images pinned in `images.yaml` only; an environment that overrides
`images.cividash.*` runs other images, which these SBOMs do not cover.

## Provided by CIVITAS/CORE

The add-on brings none of these; the CORE platform or its operator provides
them:

- Helmfile and the deployment scaffolding that includes the add-on as a component
- keycloak component: the instance realm, the client `cividash` and its roles
- secrets component: `cividash-app-key`, `db-cividash` and `keycloak-client-cividash`
- postgres component: the CloudNativePG cluster with the database `cividash`
- networkpolicies component: default deny plus the add-on's policies
- prepare component: the platform CA Secret `custom-ca-cert`, when the self-signed issuer is used
- An ingress controller and cert-manager, as configured in `global.ingress`
- Optionally Linkerd (`global.serviceMesh`)
- With `storage: volume`: a StorageClass for the media volume, `ReadWriteMany` on more than one node. With `storage: s3`: an S3-compatible bucket and a Secret with its credentials, both from the operator
